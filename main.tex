\textbf{ABSTRACT}

Local health units frequently rely on manual record-keeping protocols
and fragmented data registries, which can impede routine surveillance
and rapid outbreak tracking. To address these operational constraints,
this study develops a local-first dengue surveillance and decision
support system optimized for local health units in Davao City. It is
engineered with a Python-based computational pipeline and a relational
SQLite architecture protected by SQLCipher 256-bit AES encryption at
rest; the platform enforces data security through Werkzeug password
hashing, secure temporary credential provisioning, and Role-Based Access
Control (RBAC) to ensure strict compliance with the Data Privacy Act (RA
10173).

The system\textquotesingle s core integrates a dual-analytic approach:
historical non-parametric 75th percentile (P75) baselines establish
real-time epidemic risk tiers (Green, Yellow, Red), while a Random
Forest Regressor generates 1-week-ahead predictive case trajectories. To
support operational workflows, the platform automates outbreak warning
status notifications and populates an intervention priority watchlist
tracking barangay-level case activity (High Risk, Rising, Stable). By
combining historical statistical thresholds with machine learning
forecasting within a secure, local-first interface, the research
provides a practical digital tool for municipal health monitoring.

\textbf{Keywords:} Public Health Informatics, Dengue Surveillance,
Local-First Architecture, Statistical Epidemic Thresholds, Random Forest
Regressor, Time-Series Forecasting, Data Privacy Act (RA 10173),
Role-Based Access Control.

\subsubsection{\texorpdfstring{\textbf{1.1 Background of the
Study}}{1.1 Background of the Study}}\label{background-of-the-study}

The management of municipal epidemiological data requires structured
digital approaches that bridge aggregate reporting with operational
clarity. Modern health informatics frameworks emphasize spatial and
temporal disaggregation, wherein surveillance is executed at granular
administrative levels to capture localized transmission dynamics. Within
the Philippine health ecosystem, consolidating community-level data into
standard operational workflows depends on structured digital protocols
(Sylim et al., 2022). In urbanized administrative divisions such as
Davao City, monitoring health metrics across multiple barangays involves
considerable logistical complexity, highlighting the need for localized
tracking mechanisms to observe active Dengue transmission trends.

At the primary care level, municipal health data management frequently
relies on fragmented spreadsheets or manual logs, which can introduce
transcription bottlenecks and data synchronization delays (Kaboré et
al., 2022). Routine reviews of public health monitoring indicate that
traditional passive reporting methods using simple moving averages often
fail to flag early seasonal surges, as historical baselines can be
distorted by data anomalies (Eligado et al., 2024). Furthermore, spatial
analyses demonstrate that vector-borne disease recurrence exhibits
distinct geographic patterns, reinforcing the necessity for localized
time-series evaluations (Olana et al., 2025).

To establish reliable outbreak warnings, public health systems utilize
historical statistical thresholds to identify abnormal case surges.
Non-parametric percentile thresholding models provide robust mechanisms
for establishing baseline activity without being heavily skewed by data
extremes or outlier values (Ouédraogo et al., 2023; Rysava et al.,
2026). When paired with predictive algorithms such as Random Forest
Regression, which effectively capture non-linear temporal trends in
epidemiological data (Zhao et al., 2020; Wang et al., 2025) these
systems can support routine early warning evaluations and proactive
outbreak risk assessment. Integrating such analytical methods into
rule-based decision support logic provides health personnel with clear
operational guidance during high-caseload periods (Nguyen \& Ming,
2023).

To address these data processing and security constraints, this study
presents a local-first Web-Based Public Health Decision Support System
tailored for Dengue surveillance in Davao City (2023-2026). Developed
using a Python processing pipeline and an encrypted relational SQLite
architecture via SQLCipher (Zhang \& Yin, 2021), the system operates on
a local deployment model to maintain data availability in
low-connectivity environments (Paluyo et al., 2022; Bodducherla, 2026)
while complying with the Data Privacy Act of 2012 (RA 10173).

By structuring data ingestion, barangay-level case aggregation,
predictive regression, and rule-based alert triggers, the system
provides a local-first public health analytics and risk assessment
system for local health monitoring.

community-level interventions under secure multi-user role constraints.
To address these computational and decision-support challenges, this
research focuses on the design, development, and technical evaluation of
a local-first, web-based epidemiological surveillance system that
integrates historical 75th percentile (P75) epidemic baselines and
Random Forest regression forecasting for granular Dengue outbreak risk
assessment.

\subsubsection{\texorpdfstring{\textbf{1.5 Scope and
Limitations}}{1.5 Scope and Limitations}}\label{scope-and-limitations}

The technical scope of this study comprises the development and
evaluation of a web-based public health decision support system
incorporating an integrated analytical framework for localized Dengue
surveillance in Davao City, utilizing case data from 2023 to 2026. The
software architecture consists of a Python analytics processing engine
and a relational SQLite database configured for local-first operations
to support local data query execution during network disconnection.

The dataset is defined by standardized Dengue case attributes: Morbidity
Week, Morbidity Month, District, Barangay, Age, Sex, Clinical
Classification, and Case Classification. The system processes these
attributes through three core analytical components: Descriptive
analytics generating temporal case distributions and barangay summaries;
Predictive analytics calculating 75th percentile historical baselines
and Random Forest regression case trajectories; and Prescriptive
decision support logic executing rule-based alert triggers (Green for
Normal, Yellow for Warning, and Red for High Risk Level). Data
management complies with the Philippine Data Privacy Act of 2012 (RA
10173) by excluding personally identifiable information, including
patient names, exact street addresses, and contact details. Access
governance is structured through Role-Based Access Control (RBAC),
defining operational privileges for Barangay Health Workers (BHWs) and
City Health Officers.

System evaluation is limited to software performance metrics,
specifically database query latency (in milliseconds), data
synchronization consistency, and system interface efficiency evaluated
through technical performance profiling and component response-time
verification. It extends to operational usefulness through user-oriented
evaluations, including System Usability Scale (SUS) assessments with
BHWs, task completion timing tests, and validation of intervention
watchlists by City Health Officers. The system does not include
automated diagnostic algorithms, clinical decision support for patient
treatment, or biological sensor integration. Offline database
capabilities are limited to local record entry, querying, and reporting,
requiring active network connectivity solely for central administrative
database synchronization. Spatial and temporal analytical functions
process municipal-level records across Davao City, with system
deployment and interface assessments structured around operational
workflows typical of local health units such as those in Talomo
District.

\textbf{2.1 Municipal Epidemiological Surveillance and Barangay
Realities}

\textbf{2.1.1 The Philippine Digital Health Landscape and Local
Surveillance Constraints}

Public health information management in the Philippines involves
operational friction between centralized electronic health frameworks
and primary health facility infrastructure. While national strategies
encourage interoperable digital systems (Sylim et al., 2022), data
management at the primary care level frequently depends on manual logs
and retrospective batch reporting. Barangay Health Workers (BHWs) act as
primary data collectors within resource-constrained settings
characterized by variable network availability, hardware constraints,
and administrative workloads (De Mesa et al., 2023). Consequently,
routine surveillance records often encounter transmission delays before
reaching municipal repositories, impacting the timeliness of local data
visibility (Hartigan-Go et al., 2024).

\textbf{2.1.2 Dengue Epidemiology and Granular Surveillance in Davao
City}

In municipal settings such as Davao City, monitoring vector-borne
transmission across 182 barangays involves distinct data collection and
tracking challenges. Urban density, environmental variations, and
population movement patterns contribute to variable Dengue distribution
trends across districts.

While macro-level health statistics provide broad baseline trends,
operational monitoring requires granular, case-level records. Public
health informatics literature indicates that capturing standardized case
attributes (Morbidity Week, Morbidity Month, District, Barangay, Age,
Sex, Clinical Classification, and Case Classification) at the primary
collection point establishes the necessary data baseline required to
execute localized threshold tracking and support operational planning
(Olana et al., 2025; Paluyo et al., 2022).

\textbf{2.2 Technologies and Methodologies for Dengue Health
Informatics}

\textbf{2.2.1 Primary Data Digitization and Schema Normalization}

Transitioning from conventional paper logbooks to structured electronic
registries is an essential prerequisite for municipal epidemiological
surveillance. Replacing manual logs with digital intake pipelines
enables primary health units to eliminate recording delays inherent in
batch reporting. However, digital health initiatives in
resource-constrained municipal environments encounter operational
friction when administrative workflows overburden health personnel
(Ngusie et al., 2021). Software architectures must therefore align
system usability with structural data constraints to sustain user
engagement among primary healthcare workers (Whitehead et al., 2023).

To ensure high-integrity intake without redundancy, relational database
models built on Structured Query Language (SQL) enforce necessary
mathematical schema constraints. Applying formal normalization rules to
epidemiological variables prevents record duplication during
high-throughput ingestion (Alderden et al., 2023). Structuring core
attributes including Morbidity Week, Morbidity Month, District,
Barangay, Age, Sex, Clinical Classification, and Case Classification
within a normalized schema facilitates rapid query performance and
long-term longitudinal evaluation without compromising record validity.

\textbf{2.2.2 Edge Execution, Local-First Storage, and Secure Database
Architecture}

Deploying web-based decision support systems in settings with variable
network access requires shifting away from always-online cloud designs
(Kaboré et al., 2022). Local-first edge computing models resolve these
network limitations by processing core database transactions directly on
client hardware (Paluyo et al., 2022). As shown in edge computing
frameworks requiring stringent security, operating localized databases
with hardware-level encryption preserves continuous system availability
while safeguarding confidential health repositories from unauthorized
exposure (Bodducherla, 2026).

Integrating a local SQLite database engine with Python processing
scripts allows local health facilities to maintain uninterrupted record
entry, local querying, and offline report generation during network
outages (Krishnapur et al., 2026). Furthermore, protecting database
files at rest through standard SQLCipher 256-bit AES encryption ensures
defense against physical hardware compromise (Zhang \& Yin, 2021). Cloud
database synchronization operates as an asynchronous background routine,
preserving local system utility regardless of connectivity state.

\textbf{2.2.3 Multi-Component Analytics and Decision Support
Methodologies}

Modern epidemiological decision support systems utilize multi-tiered
analytical workflows to convert transactional case records into
actionable public health intelligence. To structure the progression from
raw intake data to decision support, the platform implements a
three-tier computational engine.

As a primary visualization layer, the platform aggregates patient
attributes into temporal morbidity trend charts, categorical
distributions (by age, sex, and clinical classification), and ranked
barangay-level risk distribution tables. This provides health officers
with immediate temporal visibility and structured spatial breakdowns
across Davao City without relying on complex GIS map rendering (Olana et
al., 2025).

To establish dynamic epidemic thresholds, the platform implements
non-parametric statistical methods utilizing historical 75th percentile
(P75) baseline calculations. By evaluating historical case
distributions, this method accounts for seasonal vector dynamics and
identifies statistical surge deviations prior to peak periods without
skewing from extreme data outliers (Ouédraogo et al., 2023; Rysava et
al., 2026).

Furthermore, tree-based ensemble machine learning models, specifically a
Random Forest Regressor, are incorporated to project 1-week-ahead case
trajectories. Comparative health informatics literature demonstrates
that Random Forest models capture complex non-linear temporal trends
with high precision compared to standard linear baselines (Zhao et al.,
2020; Kuo et al., 2024; Wang et al., 2025).

Lastly, threshold metrics and model outputs are converted into
operational decision support using deterministic rule-based logic. By
evaluating active caseloads against historical limits, the platform
automatically generates standardized early warning triggers (Green for
Normal, Yellow for Warning, and Red for High-Risk Alert) paired with
targeted intervention protocols to guide municipal response efforts
(Nguyen \& Ming, 2023).

\textbf{2.2.4 Health Data Security, Regulatory Compliance, and
Governance}

Integrating security controls into municipal health architectures is
both a regulatory requirement and a prerequisite for data integrity.
Compliance with the Philippine Data Privacy Act of 2012 (RA 10173)
requires point-of-entry de-identification, which is achieved by
excluding direct identifiers such as patient names, street addresses,
and contact numbers from the relational schema in favor of
system-generated internal keys. System access governance is maintained
through Role-Based Access Control (RBAC), restricting Barangay Health
Workers to local entry functions while reserving system administration
and account management privileges for City Health Officers or the System
Administrator.

At the application layer, credential protection utilizes salted
key-stretching algorithms via Werkzeug\textquotesingle s native security
utilities (werkzeug.security) to mitigate unauthorized access attempts.
Furthermore, local database files and configuration keys in edge
environments are secured using 256-bit AES encryption via SQLCipher to
protect against local hardware compromise.

These security mechanisms operate within a structured data management
framework, which governs records across key operational phases: data
creation, secure local storage, analytical processing, and longitudinal
retention, ensuring that historical baselines remain intact for
multi-year epidemiological comparison (Oktaviana et al., 2025; Rahul \&
Banyal, 2020).

\textbf{2.2.5 Synthesis, Research Gaps, and Proposed Technical Solution}

Public health informatics literature outlines distinct structural
attributes characterizing contemporary municipal surveillance
environments. First, a spatial resolution variance frequently occurs
because regional monitoring frameworks prioritize macro-level
administrative aggregates, leaving local health units to handle
high-resolution barangay tracking independently (Sylim et al., 2022;
Olana et al., 2025). Second, many standard operational workflows depend
on continuous network connectivity, presenting logistical challenges in
environments subject to intermittent infrastructure availability (Kaboré
et al., 2022). Third, standard health informatics architectures often
separate transactional data storage from active decision support
processing (Ngusie et al., 2021; Ouédraogo et al., 2023).

To address these architectural parameters, this research implements a
Web-Based Decision Support System configured for municipal Dengue
surveillance in Davao City. To manage spatial resolution alignment, raw
multi-year surveillance logs are processed through an automated schema
normalization pipeline that standardizes variable attributes across
reporting periods into core operational parameters (Morbidity Month,
District, Barangay, Age, Sex, Clinical Classification, Case
Classification, and Morbidity Week) for localized temporal and spatial
tracking (Alderden et al., 2023). Network constraints are addressed
through a local-first SQLite architecture paired with Python processing
pipelines, allowing offline data management, local querying, and
analytical generation prior to scheduled database synchronization
(Kleppmann et al., 2019; Paluyo et al., 2022; Krishnapur et al., 2026).
To integrate analytics within local workflows, the platform incorporates
a multi-component analytical framework: descriptive data aggregations
for temporal and categorical visualization, historical 75th percentile
(P75) threshold computations for non-parametric baseline comparisons
(Ouédraogo et al., 2023; Rysava et al., 2026), Random Forest regression
modeling for short-term case trajectory estimation (Zhao et al., 2020;
Kuo et al., 2024), and rule-based decision support logic for operational
guidance (Nguyen \& Ming, 2023).

Furthermore, data protection, access governance, and encryption
mechanisms are integrated to maintain data confidentiality, system
integrity, and compliance with RA 10173 across municipal operations
(Oktaviana et al., 2025; Zhang \& Yin, 2021).

\paragraph{\texorpdfstring{\textbf{3.2.1 Data Acquisition and

The foundational data infrastructure relies on multi-year local health
surveillance records obtained directly from the City Health Office (CHO)

epidemiological tracking profile, making it optimal for early-warning
threshold modeling.

verifying entries against reported Morbidity Weeks and hospital
admission logs. A complete listing of the data-cleaning script and

\textbf{3.2.2 Exploratory Data Analysis (EDA) and Missing Data Bias
Mitigation}

Exploratory data analysis of the multi-year municipal dengue
surveillance registries (2023-2026) obtained from the Talomo District
City Health Office (CHO) revealed structural data anomalies and
reporting discrepancies that require systematic mitigation prior to
baseline modeling. Furthermore, because institutional reporting coverage
and data archiving protocols can vary across municipal health
jurisdictions and annual reporting cycles, observed case volumes reflect
the specific administrative boundaries and operational inputs of the
contributing district.

To evaluate these inputs, an ingestion corpus was compiled from the
district\textquotesingle s annual spreadsheets, comprising a total of N
= 16,020 patient records N\_2023 = 6,548 entries in 2023, N\_2024 =
7,714 entries in 2024, N\_2025 = 224 entries in 2025, and N\_2026 =
1,534 entries in 2026). Initial evaluations of these source spreadsheets
demonstrated significant data irregularities across multiple reporting
cycles.

\textbf{3.2.2.1 Identification of Structural Anomalies and
Discrepancies}

Initial profiling uncovered substancial temporal inconsistencies within
the multi-year archives. Specifically, within the 2023 dataset, exactly
6,547 out of 6,548 records (99.98\%) contained \#REF! spreadsheet
reference errors in the Morbidity Month attribute field, leaving only 1
valid month value. Relying solely on raw database queries without
preliminary exploratory inspection would have resulted in systematic
data loss and distorted epidemiological baselines.

Further exploratory inspection across reporting periods uncovered
spatial and categorical representation discrepancies among
administrative subdivisions. In the 2024 registry spanning 18 distinct
districts, records exhibited fragmented text entries across current
address (182 unique barangays) and permanent address (195 unique
barangays) fields, leading to divergent district groupings if left
unstandardized. Exploratory cross-tabulations between clinical
classifications and laboratory outcomes also indicated reporting
variations wherein suspect cases frequently lacked confirmatory
diagnostic results during peak transmission weeks (e.g., 2,319 missing
test types and 2,447 missing laboratory results in 2024; 411 missing
results in 2026).

\textbf{3.2.2.2 Automated Imputation and Data Cleaning Protocols}

To resolve this empirical anomaly without discarding patient records,
the processing pipeline leveraged parallel morbidity week attributes to
impute and reconstruct missing monthly timelines using the integer floor
division formula:

Month = min(12, max(1, floor((Week - 1) / 4.33) + 1))

Conversely, when morbidity weeks were missing, values were estimated
from available month entries via:

Week = max(1, min(52, (Month * 4) - 2))

These empirical findings necessitated the implementation of a robust
data cleaning pipeline that systematically validated incoming records
against established epidemiological boundaries, removed duplicate case
identifiers, and standardized district nomenclature across all reporting
cycles.

\textbf{3.2.2.3 Mathematical Formulation of Epidemic Thresholds and Risk
States}

To monitor transmission intensity, epidemic thresholds for week w were
established using the 75th percentile of historical weekly confirmed
cases across baseline years (Y\_baseline):

P\_75(w) = Percentile\_75(\{C\_(y,w) \textbar{} y in Y\_baseline\})

The pre-surge warning trigger was mathematically set at 75\% of this
epidemic threshold:

PreSurge Threshold(w) = 0.75 * P\_75(w)

Classifications were subsequently governed by the following conditional
boundaries:

Normal State (Green): Current Cases \textless{} 0.75 * P\_75(w)

Warning State (Yellow): 0.75 * P\_75(w) \textless= Current Cases
\textless= P\_75(w)

High-Risk State (Red): Current Cases \textgreater{} P\_75(w)

By uncovering these underlying data artifacts through rigorous
exploratory profiling, the system ensured that subsequent non-parametric
baseline calculations and machine learning models operated on a
consistent and bias-mitigated historical repository.

\textbf{3.2.3 Non-Parametric Baseline Threshold Formulation (P75)}

succumbing to threshold distortion typical of hyper-endemic outlier
years, this study does not utilize parametric mean-variance methods in
favor of a robust non-parametric 75th percentile (P75) baseline. To
prevent data leakage and maintain a strict predictive evaluation design,
the baseline pool utilizes a rolling historical framework; for example,
when evaluating the 2026 test year, the baseline pool consists strictly
of historical data from 2023 through 2025, completely excluding the
current evaluation year from threshold construction.

\textbf{3.2.3.1 Handling of Missing and Incomplete Surveillance Data}

Real-time public health surveillance inherently encounters operational
reporting lags, administrative latencies, and incomplete morbidity weeks
during active evaluation years. Within the program architecture, the
handling of missing data is methodologically stratified between
completed historical baselines and the active test year. For historical
baseline years (2023-2025), which represent fully closed retrospective
periods, unrecorded or missing morbidity weeks default to zero case
counts.

Conversely, for the active 2026 evaluation year, the system deploys
specialized protocols to manage real-time data constraints. Surveillance
queries dynamically anchor to the latest reported morbidity week
(w\_active) rather than enforcing static calendar assumptions, thereby
preventing premature zero-imputation distortion. Furthermore, incomplete
weeks lacking synchronized case validation are isolated from active
surge ratios to safeguard weekly case velocity metrics against downward
bias, while temporal granularity is maintained by aligning weekly
historical counts (C\_y,w) against exact ISO morbidity week integers
(Weeks 1 through 52).

\textbf{3.2.3.2 Statistical Behavior of Small Sample Sizes (N=3)}

Given the constraints of the multi-year archival record, baseline
threshold calculations operate on a limited sample size of N=3 annual
observations per morbidity week. Consequently, the calculated P75 value
functions as an empirical upper quartile rather than an asymptotic
distribution limit. For each morbidity week \emph{w} across historical
baseline years \emph{y}, the endemic threshold is formulated as:

\emph{Threshold\_w = Percentile\_75( \{ C\_\{y,w\} \textbar{} y ∈
Baseline Years \} )}

Under this small sample size (N=3), the empirical distribution function
exhibits discrete ordinal stepping. Given ordered historical case counts
C(1) \textless{} C(2) \textless{} C(3), standard linear interpolation
yields:

\emph{P75 = 0.25 x C(2) + 0.75 x C(3)}

This discrete stepping behavior prevents parametric over-smoothing,
ensuring that the computed threshold accurately reflects historical
clustering patterns without making unsupported assumptions regarding
normality or continuous distribution tails.

\textbf{3.2.3.3 Operational Sensitivity Parameter and Staged Risk
Framework}

The non-parametric threshold formulation isolates baseline seasonal
endemicity from anomalous epidemic surges, drawing support from
epidemiological literature that utilizes upper quartile baselines
(Thayer et al., 2025; Nekorchuk et al., 2021). While traditional
baseline methods like the WHO quartile approach rely on the 75th
percentile to successfully balance detection sensitivity and false
alarms, studies in changing transmission environments (e.g., Nekorchuk
et al., 2021) note that rigid historical baselines must be carefully
calibrated to local trends to prevent lag in emerging outbreaks.
Operational alerts are deployed through a staged risk framework
comprising three distinct states:

Normal State (Green): Case counts remain below the pre-surge threshold
(Count \textless{} 0.75 x P75), maintaining routine monitoring and
community vector reduction activities.

Warning / Pre-Surge State (Yellow): Case counts breach the early-warning
margin (0.75 x P75 \textless{} Count \textless{} P75), prompting local
advisories and heightened surveillance.

High-Risk State (Red): Case counts exceed the full historical baseline
(Count \textgreater{} P75), triggering targeted vector control and
localized emergency response.

To establish a proactive operational buffer prior to official breaches
of the full historical baseline P75, the system incorporates a
calibration parameter where the yellow pre-surge threshold is
programmatically set at 0.75 x P75. Rather than claiming a universal
public health rule, this fractional sub-threshold functions as an
empirical sensitivity adjustment factor that intentionally trades a
higher false-positive rate for enhanced early detection. This design
guarantees that local health units secure adequate operational lead time
to mobilize resources and execute vector control before high-risk red
alerts are officially triggered.

\textbf{3.2.4 System Architecture, Security, and Machine Learning
Integration}

Building upon the validated epidemiological foundation, the technical
architecture integrates predictive machine learning models with a secure
local dashboard backend through several coordinated layers.

For predictive integration and training, time-series and classification
algorithms ingest weekly aggregated case counts, and historical lag
features to forecast local outbreak trajectories, with models trained
using rolling temporal train-test splits to simulate real-world local

Finally, the deployment interface leverages modular web templates
(dashboard.html, records.html, reports.html) to provide real-time
epidemiological tracking, automated threshold alerts, and geospatial

\textbf{3.2.6 Version Control, Repository Structure, \& Reproducibility}

\textbf{3.2.6.1 Architectural Modularity and Directory Design}

To ensure architectural maintainability, software reliability, and
verifiable deployment, the LokalHealth surveillance platform is
structured around a modular, production-ready directory layout that
strictly enforces a separation of concerns. The root repository
coordinates core system execution through a centralized entry point
(app.py), which integrates the Flask web framework, SQLCipher database
handlers, and the machine learning predictive API.

Surrounding this core engine are dedicated operational directories,
including an instance storage directory reserved for runtime-generated
and environment-specific database instances, a template directory
housing Jinja2-based views for user authentication and dashboard
surveillance interfaces, and a testing directory containing automated
test fixtures to continuously validate data ingestion and forecasting
pipelines.

\textbf{3.2.6.2 Secure State Isolation and Version Control Integrity}

To comply with healthcare data privacy requirements and prevent
accidental exposure of sensitive medical records or administrative
credentials, the repository enforces strict state isolation via version
control exclusion rules (.gitignore).

The encrypted SQLite/SQLCipher database (database.db) resides entirely
within the local instance directory and is systematically barred from
source tracking. Configuration security is further governed through
environment variable templates (.env.example), requiring explicit
administrative injection of the cryptographic passphrase
(DB\_PASSPHRASE) required to decrypt the database at runtime.

\textbf{3.2.6.3 Reproducibility and Environment Bootstrapping}

System reproducibility across distinct local or municipal server
environments is guaranteed through strict dependency management via a
pinned package specification matrix (requirements.txt). This ensures
consistent execution behavior across core analytical libraries,
including Pandas for epidemiological data manipulation, Scikit-Learn for
random forest regression modeling, and SQLCipher for encrypted
relational storage. Furthermore, to eliminate friction during initial
system deployment, the application incorporates an automated
bootstrapping mechanism that detects uninitialized environments and
securely seeds the default primary administrative account upon initial
launch, allowing immediate local-first verification and audit testing.

\textbf{3.2.7 Model \& Optimization Rigor}

\textbf{3.2.7.1 Baseline Selection and Justification}

To rigorously evaluate the system\textquotesingle s performance and
address the requirement that sophisticated models must materially
improve upon simple forecasting, a multi-tier baseline comparison is
established as a central pillar of the research design:

1. Naïve Persistence Baseline (y\_t = y\_t-1 Assumes the next
week\textquotesingle s case count equals the current
week\textquotesingle s count, serving as the baseline test for
short-term temporal continuity.

2. Historical Seasonal Median Baseline Utilizes historical median weekly
case counts from the baseline pool, capturing standard seasonal central
tendencies without complex parameter fitting.

3. Linear Regression Baseline Implements a standard linear model over
lag features and morbidity weeks to test whether non-linear ensemble
modeling is necessary.

4. Random Forest Regressor (n\_estimators=100, random\_state=42) Acts as
the proposed primary forecasting engine capable of capturing complex
non-linear seasonal and lag interactions.

For retrospective surveillance, the historical 75th percentile (P75)
threshold method is utilized as the statistical baseline. Grounded in
standard epidemiological surveillance theory (Chapter 2, Section 2.3.3),
this non-parametric baseline is traditionally deployed by municipal
health units to detect localized disease outbreaks because it mitigates
distortion from extreme seasonal outliers while establishing an
objective historical threshold for alert triggers.

For prospective forecasting, the system utilizes a Random Forest
Regressor (n\_estimators = 100, random\_state = 42) as the computational
baseline.

As established in Chapter 2 (Section 2.3.3), municipal case counts often
suffer from non-linear seasonal trends and reporting lags. While
traditional linear models (such as ARIMA or standard linear regression)
fail to capture sudden environmental outbreak shocks, the ensemble
bagging of decision trees in the Random Forest Regressor robustly models
complex non-linear feature interactions, such as past lag counts
combined with specific morbidity week indicators, without requiring
rigid data stationarity transformations.

\textbf{3.2.7.2 Hyperparameters and Tuning Strategy}

To optimize the predictive performance of the Random Forest regressor
while guarding against overfitting on historical epidemiological
records, a systematic hyperparameter tuning strategy is implemented.

For fixed configuration parameters, the random\_state is set to 42 to
ensure deterministic reproducibility across experimental runs and
validation folds, and node split quality is evaluated using a squared
error (variance reduction) criterion.

The search space for variable hyperparameters targets structural
complexity and ensemble scale. Specifically, the number of estimators
(n\_estimators) is evaluated across a discrete grid of \{50,100,200\} to
balance ensemble stability and computational efficiency. Simultaneously,
the maximum depth of the trees (max\_depth) is tested across options of
\{None,10,20,30\} to control model capacity and prevent excessive tree
expansion on fluctuating weekly case counts.

To preserve the chronological structure of epidemiological surveillance
data and prevent data leakage from future epidemic weeks into past
training folds, hyperparameter optimization relies exclusively on a
time-series cross-validation framework using walk-forward validation
principles. Candidate hyperparameter combinations are scored based on
out-of-fold Root Mean Squared Error (RMSE), ensuring that the final
selected configuration minimizes generalization error on unseen temporal
sequences.

\textbf{3.2.7.3 Evaluation, Benchmarks, and Statistical Validation}

Model performance is assessed using a dual framework combining
epidemiological predictive accuracy and software efficiency metrics. For
predictive accuracy, the system relies on the Root Mean Squared Error to
penalize larger outbreaks or missed surge peaks heavily, alongside the
Mean Absolute Error to quantify the average magnitude of absolute
forecast errors. These predictive outputs map directly into operational
warning thresholds evaluated against historical 75th percentiles
(Threshold\_w = 75th Percentile (\{C\_\{y,w\} \textbar{} y in Baseline
Years\}), categorizing municipal risk conditions as follows:

\begin{itemize}
\item
  Green (Normal): Cases \textless{} 0.75 x Threshold\_w
\item
  Yellow (Warning / Pre-Surge): 0.75 x Threshold\_w \textless{} Cases
  \textless{} Threshold\_w
\item
  Red (High-Risk / Breach): Cases \textgreater{} Threshold\_w
\end{itemize}

To complement predictive evaluation, system efficiency is benchmarked by
ensuring training times per weekly incremental update remain under 500
ms for rapid REST API response times, while maintaining resident set
size memory consumption below 150 MB to support lightweight deployment
on standard municipal server hardware.

To rigorously validate whether the Random Forest model statistically
outperforms the naive persistence, linear regression, and historical
seasonal median baselines, paired difference tests are applied to the
forecasting residuals. Residual distributions are first evaluated for
normality using the Shapiro-Wilk test (p \textgreater{} 0.05). If
normality assumptions are satisfied, a paired sample t-test is executed;
otherwise, the non-parametric Wilcoxon signed-rank test is utilized to
account for skewness, heavy tails, or outliers typical of municipal
epidemic reporting anomalies. A strict significance threshold of alpha =
0.05 is enforced across all comparative evaluations.

\textbf{3.2.8 System Evaluation and Validation}

To measure both the operational efficiency and practical utility of the
LokalHealth platform within primary care workflows, a structured
evaluation protocol is established, encompassing task-based performance,
standardized usability assessments, and health officer review.

Task completion tests were conducted to measure operational efficiency
by tracking the time in seconds required for participating Barangay
Health Workers (BHWs) to complete standard record workflows,
specifically uploading batch data template files and querying barangay
risk classifications within the local interface.

To evaluate user acceptance and system interface design, the standard
10-item System Usability Scale (SUS) questionnaire is administered to
participating BHWs to quantify perceived system usability on a 0 to 100
scale.

Lastly, practical relevance and decision-support consistency are
assessed by recording evaluator agreement levels regarding the automated
intervention priority watchlist against routine local health monitoring
standards.
